- CMS/AI 可验证页面渲染、空态和交互演示，但不计入真实接口接入或真实数据验收。

## 接口接入原则

1. 修改接口前刷新实时 Swagger，并按“页面交互 -> 现有数据/Mock -> Schema”核对需求。
2. 接口路径、方法、字段、类型、枚举、分页和响应结构以当前有效契约为准。
3. 字段差异在 `src/service/api/` 或 adapter 边界转换，不把后端 DTO 扩散到页面。
4. 所有业务 ID 作为不透明 Long 原值处理；禁止页面层使用 `Number()`、`parseInt()` 或算术转换。
5. 分开记录“Swagger 存在、API 已封装、页面已调用、真实数据已验证”，不得相互替代。
6. 真实接口失败不得回退 Mock；空数据、权限失败、后端异常和环境阻塞应明确展示。
7. 页面交互改动使用 Chrome 检查页面、接口响应、控制台和数据回显；不把无控制台错误等同于业务闭环完成。

## 跨设备承接

1. 执行 `git status -sb`；工作区干净时运行 `git fetch origin` 和 `git pull --ff-only origin main`。
2. 读取本文顶部、[AGENTS.md](../AGENTS.md) 和 [Swagger 匹配矩阵](./api-swagger-match-matrix.md)。
3. 仅在依赖缺失或锁文件变化时运行 `pnpm install`，优先复用已有 `5173` 服务和 Chrome 登录态。
4. 涉及接口时运行 `pnpm check:swagger`；TypeScript/公共逻辑变化运行 `pnpm typecheck`；业务逻辑变化运行 `pnpm test`。
5. 押金、积分、VIP 已完成最近 Chrome 读取复验；其余事项等待上述后端/环境条件后从对应恢复点继续。
